# Выкладка: password_hash() + серверная проверка входа

Порядок (сначала тестовая копия pr-diz-test.ru, потом рабочий сайт):

1. **SQL.** Выполнить `user_password_hash.sql` (расширяет `user.password` и `user.graph_key` до varchar(255)).
   Безопасно делать заранее, старый код продолжит работать.
2. **Секрет.** Добавить в `include/define.php` строку (свою, для каждого сайта отдельную):

       define('AUTH_SECRET', '<случайная строка из 64 символов>');

   Получить значение: `php -r "echo bin2hex(random_bytes(32));"`
   Без этой строки сайт покажет сообщение «Не задан AUTH_SECRET» и не откроется (так задумано).
   `define.php` в архиве нет, его у каждого сайта свой.
3. **Код.** Распаковать архив `password_hash.zip` поверх проекта (сначала должен быть выложен архив с переименованием /calculation/ → /order/: `include/header_mobile.php` построен на нём).
4. **Проверить:** вход, выход, смена пароля в «Мои настройки», создание и правка пользователя, вход по графическому ключу (`/mobile.php`).

Что увидят пользователи:
- Один раз после выкладки все получат экран входа заново (старые куки не подходят к новому токену). Пользователи резки входят так же, как раньше.
- Пароли и графические ключи переводятся на новый формат при следующем успешном входе, ничего сбрасывать не нужно.
- Секрет AUTH_SECRET нельзя менять без необходимости: после смены все выйдут, а все графические ключи в новом формате перестанут подходить (их придётся задать заново).

Когда все пользователи хотя бы раз войдут, в `include/topscripts.php` можно убрать ветку «старый формат» (`IsLegacyPasswordHash`), а в `mobile.php` и `user/index.php` убрать `or graph_key = password(?)`.
