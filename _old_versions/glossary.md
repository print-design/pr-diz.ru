# Словарь терминов проекта pr-diz.ru

Цель этого документа — фиксировать решения по названиям **по мере того, как они возникают**,
а не переименовывать что-то задним числом. Когда дойдём до отдельного пункта плана
("Пересмотр наименований"), у нас уже будет обдуманный список, а не пустой лист.

## Как этим пользоваться

- **Новый код** — сверяемся со словарём, используем уже принятые термины.
- **Новый термин возникает впервые** — обсуждаем, вносим сюда, потом используем.
- **Существующее название режет слух, но трогать его прямо сейчас рискованно** — вносим
  в раздел "Кандидаты на будущее переименование" с пометкой, где оно встречается, чтобы
  не потерять мысль, но не переименовываем в отрыве от остального кода.

## Статусы

- ✅ **Принято** — используется в новом коде.
- 🕓 **Кандидат** — существующее название, которое стоит поменять при большом проходе
  по наименованиям (пункт 5 плана), но не трогаем прямо сейчас.

## Принятые термины

| Термин (код, англ.) | Значение (рус.) | Где используется / появился | Статус |
|---|---|---|---|
| `external` (например, `externalRolls`, `externalTotals`) | "Постороннего происхождения" — не результат данного технологического процесса, а добавленное к нему извне | `CalculationRolls`: рулоны, добавленные к отгрузке, но не являющиеся результатом резки данного заказа (в БД — таблица `calculation_not_take_stream`) | ✅ |
| `shipment` | Отгрузка (юридический документ — акт-отчёт о передаче данных по отгрузке) | Новый раздел `shipment/`, таблица `shipment` | ✅ |
| `shipment_calculation` | Связь заказов с отгрузками ("многие ко многим") | Таблица-связка; записи только добавляются, никогда не редактируются/не удаляются — тот же принцип, что и у остальных `*_history`-таблиц | ✅ |
| `document_number` | Номер товарной накладной | Поле `shipment.document_number` — не просто `document`, потому что это именно номер, а не сам документ | ✅ |
| `vehicle_number` | Гос. номер транспортного средства | Поле `shipment.vehicle_number` — аналогично, не `vehicle` | ✅ |
| `cargo_type` | Наименование груза (плёнка / упаковка / этикетка) | Поле `shipment.cargo_type`; значения — PHP-константы `CARGO_TYPE_*`, как и другие подобные небольшие фиксированные наборы в проекте (`ORDER_STATUS_*`, `WORK_TYPE_*`), а не отдельная таблица-справочник | ✅ |
| `places_count` | Количество мест (грузовых) | Поле `shipment.places_count` | ✅ |
| `is_draft` / `draft_reason` / `draft_at` / `draft_by` | Механизм "перевода в черновики" — необратимая пометка недействительности юридического документа, вместо редактирования/удаления | Поля `shipment.*` | ✅ |
| `header.php` / `subheader_*.php` | Верхнее меню раздела и меню второго уровня | В каждом разделе (`plan/`, `order/`, `buh/`, `shipment/` и т.д.) верхнее меню называется просто `header.php` (раньше было `header_<раздел>.php`; `header_plan.php` → `plan/header.php`, 21.10.2026). Исключение — раздел `admin/`: там меню второго уровня (под главным верхним меню) показывается при выборе разных пунктов главного меню, поэтому файлы называются `subheader_<пункт>.php` (например, `subheader_plan.php`) и переименованию не подлежат | ✅ |
| `edition` | "Тираж" | Уже закреплён в структуре БД (`plan_edition`, класс `PlanEdition`) — используем именно это слово в новом коде, а не `printing`/`printings_number`, который для того же понятия использует `calculation/` (расхождение реальное, но менее масштабное, чем `calculation`/`order`) | ✅ |
| `cutting` | "Резка" | Уже единственный используемый вариант по всему проекту (`slitting` нигде не встречается) — разночтения не было, просто фиксируем | ✅ |
| `tuning` | "Приладка" (настройка машины перед тиражом) | Таблица БД `norm_priladka` — прямая транслитерация, трогать не будем; но в паре мест уже встречается перевод `tuning` (`machine_tuning_time`, `laminator_tuning_time`) — используем его в новом коде, а не `fitting` (нигде не встречается) | ✅ |
| `selvage` (запасной вариант — `trim`) | "Лыжи" — белые технологические полоски по краям плёнки (фотометки, цветовые эталоны), отрезаются в отход при резке на ручьи | Переименовано в существующем коде 14.10.2026: `ski`/`SKI_*`/`width_ski` → `selvage`/`SELVAGE_*`/`width_selvage` (было ~10 файлов) | ✅ |

## Кандидаты на будущее переименование

| Текущее название | Проблема | Где встречается | Заметки |
|---|---|---|---|
| `calculation` / `Calculation*` (классы, таблица) | Изначально означало "расчёт стоимости", но объект давно стал полноценным "заказом" — название вводит в заблуждение | Таблица `calculation` и связанные (`calculation_result`, `calculation_stream`, `calculation_status_history` и др.), классы `CalculationBase`, `CalculationResult`, `CalculationRolls`, переменные `$calculation`, `$calculation_id`, поля `calculation_id` во многих таблицах — около 4 800 вхождений в ~96 файлах (по состоянию на 14.10.2026) | Целевое имя — `order` (заказ): константы `ORDER_STATUS_*` уже неявно используют это слово для того же объекта. **Сделано:** раздел сайта `/calculation/` → `/order/` (октябрь 2026). **Решено** (06.11.2026): папку-заглушку `/calculation/` с перенаправлениями удалить. **Остановились на этом:** дальнейшие переименования (таблицы, классы, переменные, `calculation_id`) оставлены на потом, решение откладывается осознанно. Предупреждения на будущее: `order` — зарезервированное слово SQL, таблицу `order` пришлось бы везде писать в обратных кавычках (альтернативы — `orders`, `customer_order`); файл `order/calculation.php` оставлен с прежним именем намеренно (в нём делается именно расчёт стоимости); константа `ORDER_STATUS_CALCULATION` — это название статуса "Сделан расчёт", а не объекта, её переименовывать **нельзя**; `RENAME COLUMN` в MariaDB требует версии 10.5.2+, а на рабочем сервере предположительно 10.4 |
| `norm_priladka` (таблица БД) | Прямая транслитерация русского слова, а не перевод | Таблица `norm_priladka`, и производные (`cut_priladka`, `laminator_priladka`, `has_priladka` и т.д.) | Целевое имя для нового кода уже решено — `tuning` (см. выше). Саму таблицу пока не трогаем |
